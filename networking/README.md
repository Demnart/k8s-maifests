# Сеть в Kubernetes

## Kubernetes newtork model

Модель сети kubernetes подразуемвает следующее:

- Каждый под имеет собственный IP
- Контейнеры внутри пода имеют общий IP адрес и могут свободно обмениваться пакетами между друг дргуом
- Поды могут посылать пакеты другим подам в кластере, используя их IP адреса, без применения `NAT`
- Ограниенчения в хождении пакетов между подами определяется при помощи сетевых политик.

## Организация сетей Docker

У докер есть три модели сети: 

- Host - Контейнер использует сетевой стек хоста напрямую без какой либо изоляции. Проблема в портах. Невозможно использовать одни и те же порты с хостовой машины, в контейнерах.
- Bridge - Создает локальный виртуальный мост. Контейнеры получают изолированный IP-адреса и общаются через мост. Для доступа снаружи используется проброс портов(NAT/iptables)
- None -  полная изоляция. У контейнера есть только локальный интерфейс loopback, сетевые соединения отсуствуют
- Overlay - объединяет несколько хостов Docker
- Macvian/Ipvlan - Назначает контейнеру реальный MAC-адрес делая его видимым в фиизической сети как отдельное полноценное устройство.

## Сетевое взаимодействие с точки зрения пода в Kubernetes.

С точки зрения сети Kubernetes pod может представлять собой виртуальную машину, имеющую один ip-адрес, имеющий loopback интерфейс и все контейнеры находящиеся в рамках одного пода, могут взаимедействовать между собой по loopback интерфейс. Так же возможно настроить взаимодействие с использованием socket-файлов.

## Сетевое взаимодействия между подами на ноде.

Предположим у нас имеются два пода расположенные на ноде. С точки зрения подов, каждый под имеет свой lo, а вот с точки зрения сети kubernetes каждый под должен получить собственный ip-адрес. За выдачу ip-адресов отвечает драйвер сети kuberntes. В моем случае используемый драйвер - Cilium. В рамках Cilium используется технология EBPF и управлению сетью, выдача ip адресов(IPAM cluster pool), сохранение ip-адресов в hashmap и тд производится с помощью агентов Cilium.
